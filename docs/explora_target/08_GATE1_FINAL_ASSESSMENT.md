## 11. QA / release readiness

`READY WITH CONDITION`.

Final layers:

1. methodological;
2. input;
3. contract/schema;
4. data;
5. analytical;
6. statistical;
7. renderer;

Status normalization:

- issue/domain warning = `WARN`;
- aggregate release with nonblocking warnings = `PASS_WITH_WARNINGS`;
- unresolved human methodological decision = `REVIEW_REQUIRED`;

### What blocks Core result

- unreleased critical Spec;
- invalid contract/schema/reference;
- blocking input/data integrity issue;
- non-executable required Universe;
- invalid required Weight contract;
- unknown required Metric formula;
- analytical invariant failure.

A statistical `INELIGIBLE` or `UNSUPPORTED` result does not invalidate a valid descriptive estimate; statistical `FAIL` blocks the affected significance output.

### What blocks a renderer

- renderer value/base/significance mismatch versus Canonical Results;
- hidden required analytical warning;
- unsupported renderer contract that prevents faithful presentation.

A renderer failure does not invalidate an otherwise valid Core run.

### What blocks final release

- any unresolved blocking issue in required project/result scope;
- unresolved B3 CRITICAL review;
- official output based on unreleased critical Specs;
- required renderer failure for the artifact being published;
- missing/invalid run traceability.
