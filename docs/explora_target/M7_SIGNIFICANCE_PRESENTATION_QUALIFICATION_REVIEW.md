# M7 Significance Presentation Qualification Review

## CURRENT STATE

Gate 39A provides the authoritative `B2_CORE_SIGNIFICANCE_V1` pooled
two-proportion engine and canonical `SignificanceRelation`. The Gate 38 Master
transported comparisons in audit tables but had no declared visible significance
target. The M7 renderer already validated checksum-pinned presentation envelopes.

## TARGET STATE

Core-generated significance is transported through Canonical Results, canonical
serialization, a deterministic Render Plan, and a declared Production Master
target. Excel displays the supplied canonical marker without calculating a test.

## GAP

`EXPLORA_PRODUCTION_MASTER_V1` 1.0.0 lacked a contract-compatible visible marker
and status target. Renderer requests also required every Master slot, preventing
backward-compatible use of a Master with additional declared capabilities.

## DECISION

Version the generic Master to 1.1.0, add one literal marker target and one status
sidecar, and permit requests to select an exact subset of declared Master slots.
Target resolution remains exact and fail-closed. No statistical contract changed.

## IMPLEMENTATION

The Master now declares `significance_marker` at `presentation!E2` with status at
`presentation!H2`. `significance_qualification_request` binds one canonical
comparison, one canonical value, and one checksum-pinned presentation envelope.
The Gate 38 request explicitly retains its original three slots.

## CORE SIGNIFICANCE SOURCE

All qualification relations originate from `execute_canonical_request` and
`execute_proportion_family` under `SIGNIFICANCE_POLICY_CANONICAL.md / B2_V1`.
No relation is manually constructed as end-to-end evidence.

## CANONICAL SIGNIFICANCE TRACEABILITY

The visible marker maps to a Render Plan write whose `record_id` is the canonical
`comparison_id`. The envelope binds comparison, family, test/version, value,
slice, member, direction, run fingerprint, and token identity.

## MATERIALIZATION

Canonical JSON serialization and deserialization preserve the complete
Core-generated relation and result fingerprint. Materialization does not infer
status, confidence, direction, p-values, or tokens.

## SIGNIFICANCE RENDER PLAN

The renderer validates source identity, exact target identity, target uniqueness,
Master identity, token checksum, canonical significant status, target value,
slice/member identity, and direction before creating the write. Missing or
contradictory inputs fail closed.

## EXCEL PRESENTATION

Supported 90%, 95%, and 99% significant cases render the same `*` marker. This is
intentional: the frozen V1 presentation contract does not require visually
distinct confidence markers. Confidence remains canonical and auditable.

## NO-RECOMPUTATION EVIDENCE

Removing the canonical relation while retaining values and bases prevents request
construction and produces no marker. Non-significant and ineligible relations are
rejected as token assertions. Neither renderer, workbook formulas, nor VBA
contains a significance calculation.

## INELIGIBLE CASE EVIDENCE

Core-generated minimum-n and expected-count ineligibility remains canonical.
Both cases are preserved in audit/provenance and cannot become visible markers.
They are distinct from eligible `NOT_SIGNIFICANT`.

## DIRECTION / REFERENCE EVIDENCE

`LEFT_GREATER` and `RIGHT_GREATER` are generated by Core. Tests target the
corresponding canonical slice/value and verify the Render Plan retains the exact
comparison identity. Excel performs no value-based direction inference.

## DETERMINISM

Repeated Core input, canonical result, request, Render Plan, and render produce an
identical plan and byte-identical XLSM. Hashes are recorded in the machine-readable
evidence and checkpoint.

## PROTECTED SURFACES

Only declared marker/status and audit targets change. Renderer validation confirms
undeclared cells and untouched package parts remain exact. Formula and protected
surface mutations fail closed.

## VBA PRESERVATION

`xl/vbaProject.bin` remains byte-identical at
`0f879b60ed12315085bc722c3f59163f86ce24609e3ba6ad379069c44779b758`
before and after rendering.

## PROVENANCE

Machine-readable evidence records fixture, engine/policy, run/result/comparison,
Master, token, plan, rendered output, target, VBA, and protected-surface identity.

## VALIDATION

Focused Gate 39 covers supported confidences, eligible non-significant,
minimum-n and expected-count ineligibility, both directions, missing canonical
authority, malformed tokens, invalid references, missing targets, wrong Master,
determinism, protected surfaces, corruption, and VBA preservation. Gate 39A,
canonical, materialization, M7, Gate 38, and full regressions are required before
the review checkpoint is accepted.

## BLOCKERS

None for pooled two-proportion significance presentation qualification.

## WARNINGS

Legacy reporter significance remains for compatibility and is not canonical
authority. The presentation envelope is a human-reviewed upstream artifact under
the frozen V1 contract. Native VBA behavioral certification remains out of scope.

## COVERAGE GAPS

Welch/mean significance, charts, pivots, slicers, connections, signed packages,
broad dynamic growth, and production-wide project/metric coverage are not covered.
